# Completed 500-epoch comparisons — 28 September 2026

Both new runs completed successfully. CPU checkpoint inference reproduces their
saved overall, spatially weighted and Ek scores within a 1e-6 tolerance. No
training was launched for this analysis. All values below are percentages of
root-NMSE unless noted; lower is better.

## Results on each run's original validation set

| Model | Latent | Train / validation | Overall | u | v | w | y-weighted overall |
|---|---:|---:|---:|---:|---:|---:|---:|
| Earlier residual beta-VAE | 30 | 4500 / 500 | 51.50 | 43.51 | 66.08 | 60.67 | 58.44 |
| New residual beta-VAE | 30 | 4900 / 100 | 50.85 | 42.83 | 65.66 | 60.07 | 57.93 |
| New paper-style CNN-AE | 32 | 4500 / 500 | 46.97 | 38.78 | 61.24 | 56.41 | 50.88 |

All three trained for 500 epochs and selected epoch 500 as their best checkpoint.
The actual new CNN command used latent 32, not 30. The two 4500-snapshot runs
have identical training/validation indices and normalisation statistics. The
4900-snapshot run uses a different validation population; directly subtracting
its score from a 500-snapshot score mixes model and population differences.

## Comparison on the same 100 held-out snapshots

Reevaluating the saved models on the new residual run's validation indices gives:

| Model | Overall | u | v | w | y-weighted overall |
|---|---:|---:|---:|---:|---:|
| Residual, 4500 training, latent 30 | 51.73 | 43.57 | 66.73 | 61.18 | 58.63 |
| Residual, 4900 training, latent 30 | 50.85 | 42.83 | 65.66 | 60.07 | 57.93 |
| CNN, 4500 training, latent 32 | 48.06 | 39.47 | 63.24 | 57.90 | 51.96 |

All 100 indices belong to every model's validation set and none belong to any
training set. Each model keeps its own training-derived normalisation. Physical
root-NMSE uses the same truth fields and denominator across all three models.

The 4900-snapshot residual run reduces overall root-NMSE by 0.88 percentage points
relative to the previous residual model: a 1.71% relative root-error reduction or
3.39% reduction in squared error. Streamwise error improves by 0.73 percentage
points. This is a modest benefit, not a resolution of the gap to the CNN.

The CNN beats the new residual run by 2.79 percentage points overall and 3.36
points in u, and improves v, w and spatially weighted error as well. Its squared
error is 10.68% lower on this holdout. This establishes the ranking of these
completed runs, not a universal architecture ranking.

## Training behaviour and interpretation

Within the new CNN run, latent size and split stay fixed: overall validation
error falls from 51.86% at epoch 100 to 46.97% at epoch 500, a 4.89-point gain.
The earlier CNN's 55.32% at epoch 100 used latent 30. Comparing it with the new
final result changes both latent size and training duration; the whole change
cannot be attributed to longer training alone.

The previous residual run improves from 55.31% to 51.50% between epochs 100 and
500; the new residual run improves from 54.56% to 50.85%. Their histories use
different holdout populations. All runs still improve late in training, without
a sustained late rise in validation error. Last-100-epoch gains are approximately
0.22 points for the old residual, 0.59 for the new residual, and 0.38 for the CNN.
These curves do not justify assuming that more epochs will close the gap.

The CNN has 76,975,603 parameters versus 23,959,559 for the residual model
(3.21 times as many). Its latent vector has 32 rather than 30 values; nominal
snapshot compression is 55,500:1 versus 59,200:1, excluding model storage.
Our residual model remains smaller, but the CNN is more accurate in these runs.
Observed wall times were about 5.16 hours for the new CNN and 4.46 hours for the
new residual; these are not controlled hardware benchmarks.

Only one seed was run for each configuration. The larger training set also
changes normalisation, batch composition and optimiser updates: 154 versus 141
batches per epoch at batch size 32. This experiment therefore measures the net
effect of that training recipe, not a pure data-count effect at fixed update
budget. The shared holdout was used for checkpoint selection, so it remains a
validation comparison rather than an independent test result.

Both saved reconstruction examples retain broad structures while losing fine
scales. They show different snapshots, so they are not a controlled visual
comparison. The component metrics consistently identify v as the hardest
component to reconstruct in relative-error terms.

## Relation to the publication and next experiment

The new CNN's 46.97% overall score is numerically close to the approximately 46%
point previously read from the paper near latent 32. However, this run used 500
epochs rather than the paper's 100, and the published metric, spatial weighting,
preprocessing and official test split remain unresolved. It is not a verified
reproduction; see the 27 September report for the ambiguity in the figure caption.

A useful next controlled experiment would match the residual model to latent 32,
4500 training / 500 validation, and 500 epochs. A separate deterministic-latent
control would isolate the effect of sampling, which remains enabled in our
beta-VAE even at beta zero. Neither experiment has been prepared or launched here.

## Reproduce the analysis

From the repository root, this command performs CPU inference only:

```bash
python3 -B iteration_1_residual/analysis/compare_500_epoch_runs.py
```

It checks checkpoint architecture, disjoint splits, shared holdout membership,
normalisation agreement for the matched 4500-snapshot runs, and agreement with
saved metrics. It writes `comparison.json` (including the common indices) and
`comparison.png` to the external
`ARTIFACTS/analysis/comparison_2026-09-28/` directory. Existing training outputs
are read without modification.
